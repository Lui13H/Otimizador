01 · CONTEXTUALIZAÇÃO DO PROBLEMA

Contas em Grupo: O Caos das Dívidas Cruzadas

Em uma viagem entre amigos, pagamentos descentralizados geram grafos densos com ciclos redundantes.

O Problema na Prática

Durante uma viagem, A paga o hotel, B paga o jantar e C paga o passeio. Sem consolidação, surgem ciclos de dívida (A → B → C → A) e dezenas de transferências Pix redundantes.

Modelagem Matemática & Garantia

  • Conservação de Fluxo: A soma algébrica de todos os saldos líquidos do grupo é sempre igual a 0 (∑ saldo_i = 0).
  • Redução de Arestas: Qualquer grafo financeiro com L transações entre N pessoas pode ser liquidado em no máximo N − 1 pagamentos.
02 · ARQUITETURA DA SOLUÇÃO

Algoritmo em 4 Etapas (Pipeline de Liquidação)

Transformação estruturada da matriz bruta de despesas em transferências mínimas.

01 · Consolidar Saldos Líquidos

Acumula créditos (+valor para pagador) e débitos (−valor para recebedor) percorrendo as L linhas.

02 · Filtrar Tolerância Numérica

Remove participantes quitados ignorando ruídos de ponto flutuante: |saldo| ≤ 0,005.

03 · Ordenar com Merge Sort

Ordena os N ativos em ordem crescente (Θ(N log N)): maiores devedores à esquerda, credores à direita.

04 · Liquidar com Dois Ponteiros

Pareia esq (maior devedor) com dir (maior credor), zerando ao menos um participante por iteração.

Implementação MERGE_SORT.JS

function mergeSort(arr) {
  if (arr.length <= 1) return arr;
  const mid = Math.floor(arr.length / 2);
  const left = mergeSort(arr.slice(0, mid));
  const right = mergeSort(arr.slice(mid));
  return merge(left, right);
}

function merge(l, r) {
  const res = []; let i = 0, j = 0;
  while (i < l.length && j < r.length) {
    if (l[i].saldo <= r[j].saldo) res.push(l[i++]);
    else res.push(r[j++]);
  }
  return res.concat(l.slice(i)).concat(r.slice(j));
}

06 · ANÁLISE DE CENÁRIOS

Comportamento Assintótico: Pior e Melhor Caso

A busca linear na Etapa 1 determina a variação entre Ω(L + N log N) e O(L·N + N log N).

PIOR CASO · BIG-O
O(L·N + N log N)

Cada nome buscado via findIndex está no final do vetor de participantes, exigindo N comparações por transação.

MELHOR CASO · BIG-OMEGA
Ω(L + N log N)

Os nomes aparecem sempre nas primeiras posições da lista, tornando a busca quase imediata (O(1) por transação).

CONCLUSÃO · SEM Θ ÚNICO
∄ Θ único

Um Θ só existe quando os limites O e Ω têm a mesma ordem. Como L·N + N log N ≠ L + N log N, o algoritmo não tem Θ único.

Comparação Assintótica Detalhada

Cenário Etapa 1 (Consolidação) Etapa 3 (Merge Sort) Etapas 2 & 4 Complexidade Global
Pior Caso O(L · N) Θ(N log N) O(N) O(L·N + N log N)
Melhor Caso Ω(L) Θ(N log N) Ω(N) Ω(L + N log N)
07 · PROVA FORMAL DO MERGE SORT

Teorema Mestre & Árvore de Recorrência

Demonstração rigorosa de que T₃(N) = 2T₃(N/2) + O(N) pertence a Θ(N log N).

Aplicação do Teorema Mestre

T₃(N) = 2 · T₃(N / 2) + O(N)
  • Parâmetros: a = 2 subproblemas, fator de redução b = 2 e custo de combinação f(N) = O(N).
  • Expoente Crítico: N^(log_b a) = N^(log₂ 2) = N¹ = N.
  • Comparação (Caso 2): Como f(N) = Θ(N^(log₂ 2)), multiplicamos por log N:
T₃(N) = Θ(N log N)

08 · IMPLEMENTAÇÃO & PROVA FORMAL

Código da Liquidação e Invariante Fundamental

Por que o laço executa no máximo N − 1 iterações?

Implementação TWO_POINTERS_SETTLEMENT.JS

let esq = 0;
let dir = ativos.length - 1;

while (esq < dir) {
  const devedor = ativos[esq];
  const credor  = ativos[dir];
  const val = Math.min(-devedor.saldo, credor.saldo);

  registrarPix(devedor.nome, credor.nome, val);

  devedor.saldo += val;
  credor.saldo  -= val;

  if (Math.abs(devedor.saldo) <= 0.005) esq++;
  if (Math.abs(credor.saldo)  <= 0.005) dir--;
}

Invariante de Laço (Prova de Cotas)

A cada iteração do while (esq < dir), transferimos val = min(|saldo[esq]|, saldo[dir]). Isso garante matematicamente que:

  • Pelo menos 1 ponteiro avança (esq++ ou dir--), eliminando 1 pessoa ativa.
  • Quando restam apenas 2 pessoas (dir - esq = 1), pela conservação de soma zero, |saldo[esq]| == saldo[dir], zerando ambas simultaneamente na última transferência.

Conclusão Matemática

Como existem N participantes ativos e o último passo liquida 2 pessoas de uma só vez, o total de pagamentos é estritamente ≤ N − 1, com custo linear T₄(N) = O(N).

09 · APLICAÇÃO ENADE — QUESTÃO 01 (ANÁLISE ASSINTÓTICA)

ENADE 2014 · Notação Assintótica (O, Ω, Θ)

Relação direta com a variação entre melhor caso Ω(L + N log N) e pior caso O(L·N + N log N) do nosso projeto.

Modo Questão: Leia o enunciado e clique em "Próximo Passo da Resolução" para avaliar cada afirmativa.

Enunciado (ENADE 2014 — Questão 24)

Sejam f(n) e g(n) funções assintoticamente positivas que representam o número de operações de dois algoritmos. Avalie as afirmações:

  • I. Diz-se que f(n) = O(g(n)) se existem constantes c > 0 e n₀ > 0 tais que 0 ≤ f(n) ≤ c·g(n) para todo n ≥ n₀.
  • II. Se um algoritmo tem pior caso O(n²) e melhor caso Ω(n), então sua complexidade assintótica justa é Θ(n²).
  • III. Se f(n) = 3n log₂ n + 15n + 40, então f(n) = Θ(n log n).
A) I, apenas.
B) II, apenas.
C) I e III, apenas.
D) II e III, apenas.
E) I, II e III.

Resolução Comentada Passo a Passo

Passo 1 — Afirmação I (VERDADEIRA):
Reproduz exatamente a definição formal de Big-O (limite superior assintótico). A partir de n₀, f(n) nunca cresce mais rápido que c·g(n).
Passo 2 — Afirmação II (FALSA):
A cota justa Θ(g(n)) exige que os limites superior (O) e inferior (Ω) tenham a mesma ordem. Como no nosso projeto (que vai de Ω(L) a O(L·N)), pior e melhor casos distintos não geram um único Θ(n²).
Passo 3 — Afirmação III (VERDADEIRA):
Desprezando a constante multiplicativa (3) e os termos de menor ordem (15n + 40), prevalece o termo dominante Θ(n log n).
Passo 4 — Gabarito Oficial: Alternativa C (I e III, apenas).
10 · APLICAÇÃO ENADE — QUESTÃO 02 (TEOREMA MESTRE)

ENADE / POSCOMP · Recorrência e Teorema Mestre

Aplicação direta do Caso 2 do Teorema Mestre — o mesmo utilizado na prova do Merge Sort.

Modo Questão: Resolva a recorrência T(n) = 4T(n/2) + n² avançando os passos ao lado.

Enunciado (Estilo ENADE / POSCOMP)

O Teorema Mestre resolve recorrências da forma T(n) = aT(n/b) + f(n), com a ≥ 1 e b > 1. Considere o algoritmo de divisão e conquista definido por:

T(n) = 4 · T(n / 2) + n²

Aplicando o Teorema Mestre, a complexidade assintótica de tempo T(n) é:

A) Θ(n²)
B) Θ(n² log n)
C) Θ(n^(log₂ 4) · n)
D) Θ(n³)
E) Θ(4ⁿ)

Resolução Comentada Passo a Passo

Passo 1 — Identificar os Parâmetros:
Subproblemas: a = 4  |  Fator de divisão: b = 2  |  Custo externo: f(n) = n².
Passo 2 — Calcular o Expoente Crítico (n^(log_b a)):
log_b a = log₂ 4 = 2 ⟹ n^(log₂ 4) = n².
Passo 3 — Comparar f(n) com n^(log_b a) (Caso 2):
Como f(n) = n² = Θ(n^(log₂ 4)), há empate polinomial — idêntico ao Caso 2 usado no Merge Sort do nosso projeto!
Passo 4 — Aplicar Fórmula do Caso 2 & Gabarito:
T(n) = Θ(n^(log_b a) · log n) = Θ(n² log n).
Gabarito Oficial: Alternativa B.
